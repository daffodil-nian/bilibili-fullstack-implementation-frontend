# 搜索页「用户」信息渲染笔记（小白版）

你截图里那一张用户卡片（头像 + 可爱的小豆包 + LV0 + 签名 + UID…），  
**就是这个文件画出来的：**

```text
src/views/search/searchResult/components/UserResultList.vue
```

下面分两块讲：① 图片在哪画 ② 这种前端写法是什么意思。

### 1）左边圆形头像在哪？

就在这里：

```vue
<!-- UserResultList.vue 第 8~14 行 -->
<div class="card-cover user-avatar">
  <img
    :src="resolveAvatar(item.avatar)"
    alt=""
    @error="onAvatarError"
  />
</div>
```

含义：

- `<img>` = 真正显示图片的标签
- `:src="resolveAvatar(item.avatar)"` = 图片地址来自后端字段 `avatar`
- 如果地址坏了 / 加载失败 → `@error="onAvatarError"` 换成默认灰电视头像

`resolveAvatar` 在同文件 script 里（约 63~68 行）：

```ts
// 后端常返回：/user/1/avatar/images.jpg（相对路径）
// 有配置 VITE_COS_HOST 时，会拼成完整网址
```

你截图里是默认灰电视，说明：要么 `avatar` 路径打不开，要么走了 `onAvatarError` 默认图。

### 3）为什么会有「很多张」卡片？

因为用了 `v-for`：

```vue
<div v-for="item in list" :key="getUid(item)" class="video-card user-card">
```

`list` 是后端返回的用户数组，有几个人就循环画几张卡。

## 二、数据是怎么流到这张卡片的？（3 步）

不要被「策略模式」吓到，就记三步：

```text
① 点「用户」Tab
② userStrategy 去请求后端，拿到 userList
③ searchResult.vue 把 list 塞给 UserResultList.vue 画出来
```

### 步骤 ①②：谁去要数据？

`strategies/userStrategy.ts`

```ts
resultComponent: UserResultList,   // 告诉页面：用户用这个组件画
async fetch(...) {
  const res = await searchAll({ searchType: 2, ... })
  return res.data?.userList ?? []  // 只要用户列表
}
```

### 步骤 ③：谁把 list 交给卡片？

`searchResult.vue` 里这段：

```vue
<component
  :is="currentStrategy.resultComponent"
  :list="resultList"
/>
```

翻译成人话：

- 现在是用户 Tab → `resultComponent` = `UserResultList`
- `:list="resultList"` → 把搜索结果数组传给它
- 于是 `UserResultList` 里的 `list` 就有数据了，`v-for` 开始画卡

这就叫 **动态组件**：同一个位置，用户 Tab 画用户卡，专栏 Tab 画专栏卡。

## 三、这种前端写法到底是什么？

你原来可能习惯「一个大 vue 文件里写完所有 if」：

```vue
<!-- 以前容易写成这样 -->
<div v-if="是用户">用户卡...</div>
<div v-else-if="是专栏">专栏卡...</div>
```

我现在拆成：

| 角色 | 文件 | 干什么 |
|------|------|--------|
| 调度员 | `searchResult.vue` | 只负责 Tab、搜索、把 list 交给别人 |
| 取数员 | `userStrategy.ts` | 只负责「怎么请求用户、取哪个字段」 |
| 画家 | `UserResultList.vue` | 只负责「用户卡长什么样」 |

好处：改用户卡片外貌，**只改 `UserResultList.vue`**，不用翻一大坨搜索页。
